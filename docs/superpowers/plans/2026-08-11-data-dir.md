# Data Directory and Test Isolation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the app one configurable directory for everything it writes, and stop the test suite from touching the real one.

**Architecture:** `config.resolve_data_dir()` returns an absolute path anchored to the project root. `app.py` creates it and `os.chdir`s into it once, at import, above the logger setup — so every existing relative write (`logs/`, `.cache/`, `prompts.db`) follows with no call-site changes. Tests use the identical mechanism via one autouse `monkeypatch.chdir(tmp_path)`, which replaces three ad-hoc fixtures.

**Tech Stack:** Python 3.14, Flask, loguru, pytest, `pathlib` (stdlib).

**Spec:** `docs/superpowers/specs/2026-08-11-data-dir-design.md`

## Global Constraints

- **Indentation: 4 spaces** for Python. Every existing file in this repo uses it.
- **Parenthesise sub-expressions** where precedence could be ambiguous — the repo owner's style.
- **No new dependencies.** `pathlib`, `os`, `subprocess`, `sys` are stdlib. `requirements.txt` is not touched.
- **`[paths] data_dir` default is `"."`** — this change must be a complete no-op for an existing install.
- **`resolve_data_dir()` is pure.** It computes and returns a path; it does **not** create directories. The `mkdir` belongs at the call site in `app.py`. This keeps its tests free of filesystem side effects — a test asserting the relative-path case must not create a stray directory in the project root.
- Run tests as `source venv/bin/activate && python -m pytest -q` from the project root. Bare `pytest` also works (there is a `pytest.ini` with `pythonpath = .`).
- Baseline before starting: **125 passing** (114 plus 11 `browser`-marked). After this plan: **134**.
- The browser tests need a working Firefox and network for the htmx CDN; they skip cleanly otherwise. Use `-m "not browser"` for fast iteration, but run the full suite before each commit.

```python
    assert config.resolve_data_dir() == config._BASE_DIR


def test_resolve_data_dir_relative_anchors_to_project_root(monkeypatch):
    monkeypatch.setattr(config, "_settings", {"paths": {"data_dir": "vardata"}})
    assert config.resolve_data_dir() == (config._BASE_DIR / "vardata")


def test_resolve_data_dir_absolute_wins(monkeypatch, tmp_path):
    target = tmp_path / "elsewhere"
    monkeypatch.setattr(config, "_settings", {"paths": {"data_dir": str(target)}})
    assert config.resolve_data_dir() == target


def test_resolve_data_dir_blank_falls_back_to_project_root(monkeypatch):
    monkeypatch.setattr(config, "_settings", {"paths": {"data_dir": "   "}})
    assert config.resolve_data_dir() == config._BASE_DIR


def test_resolve_data_dir_creates_nothing(monkeypatch):
    """It is a pure computation — the mkdir belongs to the caller."""
    monkeypatch.setattr(config, "_settings", {"paths": {"data_dir": "should-not-appear"}})
    result = config.resolve_data_dir()
    assert not result.exists()
```

Note for the implementer: `test_resolve_data_dir_creates_nothing` is the guard for the Global Constraint above. If someone later adds a `mkdir` inside `resolve_data_dir()`, this test fails **and** the previous run will have left a `should-not-appear/` directory in the project root, which is the visible symptom.

- [ ] **Step 3: Write the implementation**

Append to `config.py`, after the `Config` class:

```python
def resolve_data_dir() -> Path:
    """Absolute directory for everything the app writes.

    Anchored to the project root the same way the settings files are, so the
    app reads and writes the same place no matter where it was launched from.
    Pure: the caller creates the directory.
    """
    configured = str(_get("paths", "data_dir", ".")).strip()
    if (not configured):
        configured = "."
    return (_BASE_DIR / configured).resolve()
```

`Path` is already imported at `config.py:3`.

Note: `(_BASE_DIR / configured)` handles the absolute case for free — `pathlib` discards the left operand when the right is absolute.

Notes for the implementer:

- Do **not** add `os.makedirs("logs", exist_ok=True)`. Loguru's file sink creates missing parent directories itself — verified empirically in an empty directory. A review flagged this as a first-run crash; it is a false positive, and the spec records it as such.
- Do **not** move the chdir into the `if __name__ == "__main__":` block. It has to happen at import so a WSGI server importing `create_app` behaves the same as `python app.py`, and so it precedes `logger.add`.
- Nothing else in `app.py` changes. `_cache_artifact` keeps its signature.

### Task 3: Consolidate test isolation onto one fixture

**Files:**
- Modify: `tests/conftest.py` (remove `_isolated_prompt_db`, add `_isolated_cwd`)

- Modify: `tests/test_cache_artifact.py` (remove its local `_isolated_cwd`)

**Interfaces:**
- Consumes: nothing from Tasks 1–2 at runtime; this task is independent of them and could ship alone.
- Produces: an autouse `_isolated_cwd` fixture in `tests/conftest.py` covering every test in the suite.

**Why these test changes are mandatory, not optional:** a chdir only protects code that runs *inside* the test. **Four** tests start a **real** daemon thread — `test_generate_image_job_starts`, `test_generate_dashscope_image`, `test_generate_records_prompt_in_history` and `test_generate_does_not_record_blank_prompt` — because unlike their neighbours they do not patch `threading.Thread`. (An earlier revision of this plan said there were only two; that was wrong and the review caught it. Re-derive the list with `grep -n "threading.Thread" tests/test_routes.py` and check which `/generate` tests are NOT in it, rather than trusting this sentence.) If such a thread reaches `_cache_artifact` after the test returns and `monkeypatch.chdir` has unwound, the write lands in the real `.cache/`. That is precisely the bug this plan exists to eliminate, so all four must be made synchronous in the same commit that deletes `_no_artifact_writes`.

- [ ] **Step 1: Write the failing leak-canary test**

Append to `tests/test_routes.py`:

```python
def test_generate_does_not_write_into_the_project_root(client):
    """The assertion whose absence let the suite destroy the real .cache/.

    Deliberately does NOT patch _cache_artifact — the real one must run, or
    this proves nothing. It DOES run the job synchronously, because a
    background thread could otherwise still be in flight when the assertions
    run, and the canary would pass on a race rather than on correctness.
    """
    import config

    root = config._BASE_DIR
    cache_dir = root / ".cache"
    created_cache_dir = (not cache_dir.exists())
    cache_dir.mkdir(exist_ok=True)
    canary = cache_dir / "CANARY-leak-test"
    canary.write_text("planted by the leak canary test")
    entries_before = set(cache_dir.iterdir())
    db_existed = (root / "prompts.db").exists()

    try:
        with patch("app.image_gen.generate_image", return_value=b"png-bytes"), \
             patch("app.threading.Thread") as mock_thread:
            mock_thread.side_effect = lambda target, args, daemon: \
                type("T", (), {"start": lambda self: target(*args)})()
            client.post("/generate", data={
                "output_type": "image",
                "prompt": "leak canary prompt",
            })
        client.get("/")

        assert canary.exists(), "the suite deleted files from the real .cache/"
        assert set(cache_dir.iterdir()) == entries_before, \
            "the suite wrote artifacts into the real .cache/"
        assert (root / "prompts.db").exists() == db_existed, \
            "the suite created a prompts.db in the project root"
    finally:
        canary.unlink(missing_ok=True)
        if (created_cache_dir and cache_dir.exists() and (not any(cache_dir.iterdir()))):
            cache_dir.rmdir()
```

## Out of Scope

Per the spec:

- Separate `cache_dir` / `log_dir` keys. One `data_dir` covers the need.
- Migrating existing data to a newly configured `data_dir` — that is a manual `mv`.
- Changing the `logs/` subdirectory name.
- Saving and restoring the working directory when the process exits. With the default `"."` and pytest run from the project root the chdir is a no-op; the spec records this as accepted.
